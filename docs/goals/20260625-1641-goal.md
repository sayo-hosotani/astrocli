# Goal

## Objective

Codexと協力して、仕様作成、goal設定、実装、テスト、次のgoal作成を繰り返せるプロジェクト運用を整備する。

## Requirements

### Documentation Structure

- `goal.md` には、Codexが作業を進めるために必要な目的、要件、達成条件だけを書く。
- 検討経緯や意思決定の背景は `docs/notes/yyyymmdd-hhnn-note.md` に書く。
- 現在有効なgoalは `goal.md` に書く。
- goalの履歴は `docs/goals/yyyymmdd-hhnn-goal.md` に保存する。
- Codexとの会話の議事録は `docs/notes/yyyymmdd-hhnn-note.md` に保存する。
- `plan.md` は使用しない。

### README.md

- アプリの目的を書く。
- アプリのコンセプトを書く。
- 技術的ではないドメイン知識を書く。

### AGENTS.md

Codexが最初に読む入口として、各ドキュメントの役割、rulesの参照方法、skillsの参照方法を書く。

含める内容:

- `README.md` をいつ参照するか。
- `goal.md` をいつ参照するか。
- `.agents/rules` をどのように参照するか。
- `.agents/skills` をどのように参照するか。
- rulesとskillsをどのように使い分けるか。
- 議事録とgoal履歴の保存場所。
- `plan.md` を使わないこと。

### Rules

Codexとの作業ループを `.agents/rules` にルールとして記載する。

含める内容:

- Codexと会話して、実装または改善したい内容をgoalとして整理する。
- 会話内容の要点を議事録として `docs/notes/yyyymmdd-hhnn-note.md` に保存する。
- 現在有効な仕様と達成条件を `goal.md` に書く。
- goalの履歴を `docs/goals/yyyymmdd-hhnn-goal.md` に保存する。
- ユーザーが承認した場合のみ、`goal.md` の内容をCodexのgoalに設定する。
- Codexのgoalに到達したら、次のgoalについてユーザーと会話を始める。
- `goal.md` は作業サイクルごとに変わるため、恒久的に守るべき重要事項は `.agents/rules` に書く。
- 繰り返し使う作業手順、判断基準、コマンド、チェックリストは `.agents/skills` に書く。

### Skill Creation Rule

`.agents/rules` に、skillsに何を書くか、いつskillsを作るかを記載する。

含める内容:

- 複数回使う作業手順はskillにする。
- ビルド、テスト、リリース、仕様更新、議事録作成、goal設定などの手順はskillにする。
- 手順にコマンド、確認観点、成果物がある場合はskillにする。
- 一度きりの作業内容や現在のgoalはskillにしない。
- 恒久的な判断基準や禁止事項はskillではなくruleにする。

### Skills

プロジェクトで使用する作業手順やスキルを `.agents/skills` に保存する。

初期候補:

- 議事録作成手順
- goal作成手順
- goal設定手順
- goal達成確認手順
- ビルド手順
- テスト手順

## Acceptance Criteria

- `README.md` が作成され、アプリの目的、コンセプト、技術的ではないドメイン知識を書く場所として定義されている。
- `AGENTS.md` が作成され、Codexがrulesとskillsをどのように参照すればよいかが書かれている。
- Codexとの作業ループが `.agents/rules` に記載されている。
- 重要事項は `goal.md` ではなく `.agents/rules` または `.agents/skills` に書く、というルールが `.agents/rules` に記載されている。
- skillsに何を書くか、いつskillsを作るかが `.agents/rules` に記載されている。
- 初期skillsが `.agents/skills` に作成されている。
- `plan.md` が使用されない運用になっている。
