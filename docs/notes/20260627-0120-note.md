## Final Result

調査完了。

確認したリポジトリ:

- `SharpAstrology.SwissEph`
- `SharpAstrology.Base`
- `SharpAstrology.West`

調査結果:

- `SharpAstrology.SwissEph` は `IEphemerides` を実装しており、`HouseCuspPositions(DateTime pointInTime, double latitude, double longitude, HouseSystems houseSystems = HouseSystems.Placidus, EphCalculationMode mode = EphCalculationMode.Tropic)` を公開している。
- `HouseSystems` enumには `Placidus` が存在する。
- `SharpAstrology.SwissEph` 内部には `PlacidusHouseSystem.cs` があり、Swiss Ephemerisの `swehouse.c` 由来のプラシーダス計算を移植している。
- `HouseCuspPositions` はUTC `DateTime` を要求する。
- 戻り値は `HousePosition` で、`HouseCusps` と `Cross` を持つ。
- `Cross` には `Asc`、`Dc`、`Mc`、`Ic`、`Vertex` が含まれる。
- NuGetには `SharpAstrology.SwissEph` 0.4.2 と `SharpAstrology.Base` 0.12.0 がある。
- `SharpAstrology.SwissEph` は `net10.0` 対応で、AstroCLIの現在のターゲットと一致する。
- README上は `EphType.Moshier` を使えばSwiss Ephemeris/JPLファイルなしで計算できる。
- Swiss/JPLファイルを使う場合は、ephemerisファイルを別途配置してパス指定する。
- `SharpAstrology.West` はREADME上でexperimentalとされており、主に西洋占星術のアスペクト関連。今回のハウスカスプ計算には必須ではない。
- NuGetパッケージ `SharpAstrology.SwissEph` 0.4.2 の中身は `lib/net10.0/SharpAstrology.SwissEph.dll`、README、ライセンス類で、`runtimes/` 配下のネイティブDLLは含まれていない。
- `SharpAstrology.SwissEph.csproj` のPackageReferenceは `System.Numerics.Tensors` と `SharpAstrology.Base` で、C由来のネイティブDLL依存は見当たらない。
- `EphemerisContextBuilder` ではMoshierがデフォルト有効。`UseSwissEphFiles(...)` や `UseJplFile(...)` を呼ばない限り、天文暦ファイルやJPLファイルは必須ではない。
- `MoshierBodyPositionSource` はfile-less sourceとして実装されており、Sun、Moon、Mercury through Plutoなどを提供する。

重要な制約:

- `SharpAstrology.SwissEph` はAGPL-3.0。
- Swiss Ephemeris由来部分はAGPLまたはSwiss Ephemeris Professional Licenseの選択が必要。
- AGPLを選ぶ場合、配布または公開サービス化するソフトウェア全体のライセンスに影響する可能性がある。
- そのため、技術的には素直に使えるが、AstroCLIに恒久依存として追加する前にライセンス方針をユーザー確認する必要がある。

評価:

- 技術面: 使いやすい。`HouseCuspPositions` を呼ぶだけでプラシーダスカスプを取得できる。
- 精度面: Swiss Ephemeris移植由来なので、プラシーダスについては自力計算より期待できる。
- 運用面: `Moshier` なら追加ファイルなしで始められる。Swiss/JPLファイルを使う場合はデータ管理が必要。
- ライセンス面: AGPLが最大の懸念。ここが許容できない場合は、そのまま依存する案は避けるべき。
- 実行要件: 検証用にMoshierだけで始めるなら、C#ライブラリ単体で動く見込み。ネイティブDLLや天文暦ファイルの導入は不要。

SharpAstrology.SwissEphのライセンス制約を承知したうえで、まずは検証用途としてプラシーダスのハウスカスプ計算を調査実装する。

- `SharpAstrology.SwissEph` を追加する。
- UTC日時、緯度、経度を渡して `HouseCuspPositions(..., HouseSystems.Placidus)` を呼ぶ。
- JSON出力に `houses.system = "placidus"` と `houses.cusps.house1` から `house12` を追加する。
- `ascendant` は既存の自前計算と `HouseCuspPositions` の `Cross[Asc]` を比較する。
