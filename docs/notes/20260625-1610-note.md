## Topic

Codexを使って仕様作成、goal設定、実装、テストを進めるためのプロジェクト運用フローを検討した。

## Discussed Flow

1. Codexと会話して仕様をまとめる。
2. 議事録を `docs/notes/yyyymmdd-hhnn-note.md` に保存する。
3. 現在の仕様を `plan.md` に書く。
4. 歴代の仕様を `docs/plans/yyyymmdd-hhnn-plan.md` に保存する。
5. 仕様が定まったら `goal.md` を作成し、Codexのgoalに設定する。
6. 歴代のgoalを `docs/goals/yyyymmdd-hhnn-goal.md` に保存する。
7. goalに到達したら、再びCodexと会話して次の仕様をまとめる。

## Documentation Policy

- `README.md` にはアプリの目的、コンセプト、技術的ではないドメイン知識を書く。
- `.agents/rules` にはプロジェクトのルールをすべて書く。
- `.agents/skills` にはプロジェクトで使用するスキルを書く。
- ビルドコマンドやテストコマンドなどの作業手順も `.agents/skills` に書く。
- `AGENTS.md` には、どこに何が書いてあるかを書く。
- `AGENTS.md` には、いつスキルを使うのか、いつルールを参照するのか、スキルやルールがどこにあるのかを書く。

- 現在有効なgoalは `goal.md` に置く。
