## Current Understanding

AstroCLIは、占星術チャートを最終的な出力対象にしつつ、初期段階では天文情報のテキスト出力から始める。

最初の仕様検討では、いきなり本格的なホロスコープ出力を作らず、CLIの入出力、日時と場所の扱い、出力する天体情報、採用する天文計算ライブラリ、検証方針を決める必要がある。

## CLI And JSON Parity Input

整理したこと:

- 初期MVPではJSONインポートとJSON保存は実装しない。
- ただし、将来追加しやすいようにCLI入力と内部設定モデルを分ける。

追加の未決事項:

## CLI And JSON Priority Decision

## Plan Do Replan Done Rule

ユーザーから、`plan.md` は廃止したが、goalを進めるには作業planが必要だという指摘があった。

決定:

- 調査または実装を始める前には、必ず作業planを立てる。
- ここでいうplanは `plan.md` ではなく、調査や実装を進めるための作業計画を指す。
- 実際に調査または実装を進めて、planを変える必要が出た場合は、作業planを立て直す。
- plan、do、replan、do、doneの流れは、議事録 `docs/notes/yyyymmdd-hhnn-note.md` に記録する。

議事録には必ず次を含める。

- もともとのplanは何か。
- planから何を変更したか。
- planをどうして変更したか。
- planをどのように変更したか。
- 最終的にどうなったか。

反映:

- `.agents/rules/workflow.md` に恒久ルールとして追加した。

## Plan TODO Rule

ユーザーから、作業planは細かくTODOにして、DONEするたびにチェックし、実行漏れがないようにしたいという補足があった。

決定:

- 作業planは細かいTODOとして記載する。
- TODOは見出しごとに分けて管理する。
- 各見出しには、そのTODO群をplanに含めた理由や特記事項を記載する。
- TODOを完了するたびに、完了したことが分かるようにチェックする。
- 不要になったTODOは削除しない。
- 不要になったTODOは、不要になったこととその理由が分かるように記録する。
- plan/do/replan/do/doneの議事録にも、各TODOの完了状態、不要状態、見出しごとの理由や特記事項を残す。

反映:

- `.agents/rules/workflow.md` に恒久ルールとして追加した。

## Plan TODO Reason Adjustment

ユーザーから、TODOごとに理由を書くと大変なので、TODOを見出しごとに分けて管理し、見出しごとに理由や特記事項を書いたほうが楽そうだという補足があった。

決定:

- TODOごとの理由記載は必須にしない。
- TODOは見出しごとに分けて管理する。
- 見出しごとに、そのTODO群をplanに含めた理由や特記事項を書く。
- TODO単位では完了チェックと不要状態の記録を重視する。

反映:

- `.agents/rules/workflow.md` のPlan Do Replan Doneルールを更新した。

## Stop And Confirm Rule

ユーザーから、中断条件について追加説明があった。

決定:

次の問題が発生した場合は、作業を停止してユーザーに確認を取る。

- 権限問題が発生した場合。
- goalを達成できないと判断した場合。
- planした時点で、goalにたどり着けるだけの材料が集まっておらず、ユーザーへの確認が必要な場合。
- plan変更が当初のユーザーの指示から逸脱する場合。
- plan変更がユーザーの指示からは逸脱しないが、回避策が迂遠、非常にトリッキー、または影響範囲が大きくなりすぎる場合。
- plan変更中に既存仕様との矛盾を発見した場合。

停止時には、発生した問題、現在のplanとの差分、続行する場合の選択肢、推奨する対応を簡潔に説明する。
