## Plan Changes

### Replan 1

変更したこと:

- `dotnet new` 実行時に `DOTNET_CLI_HOME=/home/ubuntu/astrocli/.dotnet-home` を指定する。

変更理由:

- `dotnet new` が `/home/ubuntu/.templateengine/dotnetcli/10.0.108` に書き込もうとして、読み取り専用ファイルシステムで失敗したため。
- 作業自体はユーザー指示から逸脱せず、ワークスペース内に.NET CLIの作業ディレクトリを置くだけで解決できるため、停止確認ではなくreplanで続行する。

変更後のplan:

- Project Skeletonの各 `dotnet new` コマンドは、`DOTNET_CLI_HOME` をワークスペース内に向けて実行する。

### Replan 2

変更したこと:

- 誤って追加したNuGetパッケージ `Astronomy` を削除する。
- 正しいNuGetパッケージ `CosineKitty.AstronomyEngine` を追加する。

変更理由:

- `Astronomy` パッケージのAPIを確認したところ、`cosinekitty/astronomy` ではない可能性が高かった。
- NuGet検索で `cosinekitty/astronomy` に対応するパッケージが `CosineKitty.AstronomyEngine` であることを確認したため。

変更後のplan:

- Astronomy Engine Integrationでは `CosineKitty.AstronomyEngine` を使用する。

### Replan 3

変更したこと:

- 太陽/月の黄経取得に `Astronomy.EclipticLongitude` を直接使わない。
- `Astronomy.GeoVector(body, time, Aberration.Corrected)` で地心ベクトルを取得し、`Astronomy.EquatorialToEcliptic` で黄道座標へ変換して `elon` を使う。

変更理由:

- `Astronomy.EclipticLongitude` はドキュメント上、太陽中心の黄経であり、太陽も指定不可のため、西洋占星術のネイタル向けに必要な地球視点の太陽/月黄経に合わない。

変更後のplan:

- Astronomy Engine Integrationでは、地心ベクトルから黄道座標へ変換する方針で実装する。

### Replan 4

変更したこと:

- ビルドとテスト確認は並列ではなく直列で実行する。

変更理由:

- CLIプロジェクト単体ビルドとテストプロジェクトビルドを並列実行したところ、同じ `AstroCli.deps.json` に同時アクセスして片方が失敗したため。
- テストプロジェクトビルド自体は成功しており、コードの問題ではなく並列実行による出力ファイル競合と判断したため。

変更後のplan:

- 以後の `dotnet build` / `dotnet test` は直列実行で確認する。

### Replan 5

- プロジェクト単位のビルドは成功しており、実装コードではなく `.slnx` の扱いに起因する問題と判断したため。
- `.sln` は標準的で、影響範囲が小さい回避策であるため。

変更後のplan:

- `.slnx` は不要になったが、削除せず不要状態として扱う。

- `AstroCli.sln` と `AstroCli.slnx` は作成済みだが、現時点の検証手順では不要として扱う。
